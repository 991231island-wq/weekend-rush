# 意向规划与快捷调整

## 少问，先接过决策

“这周末杭州去上海，两天，看看建筑、吃点好的，不要太累。”

先用一句话复述意向，把缺失的预算上限、最早出门/最晚到家等关键条件集中询问。不要索要车次号、POI ID、景点清单或酒店坐标；没有必去点时自己推荐，不根据用户设计经历臆测本次旅行兴趣。

区分阶段：灵感草案可先推荐片区和体验组合；查询草案已有日期/城市，开始验证工具数据；推荐方案需要无未处理硬错误，未知费用、开放和预约仍待确认。“懒人”是默认做可逆推荐并方便修正，不是放宽硬约束或替人下单。

## 推荐准则

1. 提取兴趣和排除项，例如建筑、街区、地方小吃，排除购物和高强度长走。依据这些准则筛选，说明具体理由。
2. 按片区/类型查询适量候选，保留地址、类别和 ID；结合兴趣、相邻路线、开放风险、停留和费用取舍。住宅/地铁站等可用类别排除的同名项主动排除；仍有多个合理对象才问用户。
3. 两天都有活动目的、用餐和休息。留白说明是休息、机动还是主动选择，不用四小时候车掩盖没有安排。紧凑片区和可删减点通常比反复横穿城市更合适，用真实路线核实。
4. 餐饮随片区查询，提供具体候选或明确区域/菜系、时间窗、预留和替代；明确饮食禁忌是硬约束。POI 存在不等于当天营业或价格已核实。
5. 住宿兼顾首日终点、次日动线和返站；无房价/房态数据时只给区域及参考点，金额标为预留，不声称指定酒店在预算内有房。已订酒店是固定锚点。
6. 车次按整个可用时段、接驳、费用和回家期限推荐；用户不指定车站时自己比较有意义的候选。展示推荐与备选，把全量列表留作依据。

## 可直接照着走的输出

先呈现推荐理由和关键选择，再按日期展开：

- 起止时间、具体地点/地址、做什么、停留时长、为什么推荐。
- 离开住处、进出站、去程、返程、到家；接驳未知则明确估时。
- 相邻路段交通方式、路线耗时和步行，带来源与查询时间。
- 用餐时间、区域/已查具体餐馆、菜系/理由、费用预留和替代。
- 休息、找路、排队缓冲；住宿区域/参考点及预订状态。
- 已知票价、估算预留、未知费用分别展示，给出出发前必办与待核实事项。

轻松备选先摘要比较活动取舍、已查路线步行与休息；信息不足不能编造优化百分比。脚本只验证已有字段，助手仍需检查偏好覆盖、吃住完整性和营业依据。

## 一句话调整

| 用户请求 | 应有行为 | 不能悄悄改变 |
| --- | --- | --- |
| 这个不喜欢 | 指代明确则移除并更新排除偏好，推荐同片区替代并查前后路线 | 必去点、已完成活动、已买票 |
| 第二天轻松点 | 减可选活动/折返、延长休息、重算接驳 | 最晚到家等硬约束 |
| 想多吃一点 | 同片区加餐饮体验，减少低优先活动，重算预留 | 禁忌、预算上限 |
| 晚一小时出门 | 检查是否错过去程；未买票可查后续有票班次，已买票说明冲突 | 凭空顺延原列车时刻 |
| 排队多半小时 | 以当前时间位置传播延误，复核剩余衔接 | 已完成活动与历史版本 |
| 累了，别走了 | 查公交与就近休息，删可选点；查不到说明缺口 | 静默新增超预算打车 |
| 这里逛完了 | 固定完成状态，只改后续 | 已完成活动的时间、地点、费用 |

调整返回新版本、理由、受影响时段、费用/步行/到家变化及待确认项；原版本留存，不重新填写全部需求。
