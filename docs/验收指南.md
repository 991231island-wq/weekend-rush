# 第一轮验收：界面与规则示例

打开 http://127.0.0.1:4173 。本轮使用固定的杭州—上海模拟数据，不需要 GitHub 或高德 Key。每个独立场景开始前刷新页面，以免上一次调整影响判断。

| 操作 | 预期结果 |
|---|---|
| 分别点击“经典多逛”和“慢一点也好” | 选中状态和时间线切换；后者的预计步行更少、休息更多。费用由各活动汇总，明确标为估算。 |
| 在“经典多逛”点击“晚出发 1 小时” | 版本变为 02；移除一个可选点，未完成的当天活动时间变化，保留必去点；显示修改理由。这里只演示固定规则调整，不含重新查票或改签。 |
| 刷新，点击“今天有点累” | 步行总距离降低，费用与活动说明更新，显示减少步行的代价。 |
| 刷新，将“人民广场”标记完成，再点击“今天有点累” | 已完成标记及原活动时间保留，调整发生在未完成安排。 |
| 刷新，编辑每人预算为 700 元 | 两份当前样例都显示“需要调整”；不自动编造更便宜的新方案。 |
| 刷新，预算保持 1000 元，最晚到家改成 18:00 | 样例到家时间为 18:20，两份方案均显示“需要调整”。 |

验收时请重点判断：能否看懂两份方案的取舍、时间线是否易读、变化后的原因是否清楚、待核实与估算标记是否足够明显。任一操作没有出现表中结果，或结果有误导，都记录为问题。
