# 吃、住、门票与营业信息来源调研（2026-10-16）

本轮只核对来源和接入条件，尚未调用新的旅行平台接口。目标是让行程能区分**地点参考信息、具体日期的报价、场馆规则和真实预订状态**，不把地图人均消费当餐费，也不把通常营业时间当作出行日已营业。

| 信息 | 首选来源 | 能确认什么 | 当前可用性与缺口 |
|---|---|---|---|
| 餐饮候选、参考人均、常规营业时间 | 已接入的高德地点详情；[高德 POI 2.0 文档](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch) | 文档列出 `cost`、`opentime_today`、`opentime_week` 等；当前 MCP 联调实际得到部分地点的参考消费和营业文本 | 已可用于推荐和餐费估算；不能假设当前 MCP 一定返回 2.0 文档的全部字段。人均消费不是菜单报价，常规营业时间不保证节假日或计划当天营业。 |
| 某餐厅的实际菜单与报价 | 门店自己的菜单、官网或官方小程序；例如[餐厅公开菜单](https://www.thefellasrooftop.com/en/menu/index.html) | 明确的菜品或套餐标价及适用说明 | 信息分散，没有找到可供个人作品普遍查询所有餐厅菜单的开放接口。只在有可核对的具体菜单时引用，仍需留意时效、服务费和售罄。 |
| 酒店候选与指定入住日期 | [飞猪 AI 开放 Skill](https://flyai.open.fliggy.com/docs)、[官方命令说明](https://github.com/alibaba-flyai/flyai-skill) | 酒店搜索支持入住、离店日期、位置、房型和价格筛选，并提供商品跳转入口 | 可作为下一轮优先试验的开放渠道；[官方 FAQ](https://flyai.open.fliggy.com/docs/faq)说明部分波动较大的产品不返回价格，应引导用户到 `jumpUrl` 看最新报价。接口有响应不等于已核实房型、税费、退改和房态。正式 Key 可从[控制台流程](https://flyai.open.fliggy.com/docs/quickstart)取得，免 Key 体验的覆盖与额度尚未实测。 |
| 某家酒店的最终房价和入住规则 | 酒店自己的预订页；例如[洲际酒店官方预订页](https://www.ihg.com.cn/intercontinental/hotels/cn/zh/shanghai/shgwr/hoteldetail) | 选定日期、入住人数和房价计划后查看对应房价及条款 | 适合在用户选中酒店后复核，无法作为所有酒店的统一查询接口；页面上的“起价”不能直接计入预算。 |
| 景点门票、场馆开放与预约规则 | 景点/场馆**当期官方公告和售票页**；例如[豫园游览指南](https://www.yugarden.com.cn/Page/WxyGarden/notice.html)、[上海博物馆人民广场馆当期参观信息](https://www.shanghaimuseum.net/mu/frontend/pg/m/service/visit-west) | 票种、季节价、开放/停止入场时间、闭馆日、预约入口和例外公告 | 权威性高，但没有统一接口。须核对具体场馆、展览及出行日期；同一场馆旧版常规须知可能与[当期特展票务公告](https://www.shanghaimuseum.net/mu/frontend/pg/m/article/id/I00005037)不同。 |
| 景点票务商品发现 | [飞猪 AI 的 POI 搜索](https://github.com/alibaba-flyai/flyai-skill) | 可找景点和可跳转的票务商品 | 是否返回特定日期、票种的最终价和可售状态，需要用样例实际验证；价格缺失时按[官方 FAQ](https://flyai.open.fliggy.com/docs/faq)给跳转入口，不能填猜测金额。 |

两个更深的数据渠道适合在合作权限明确后考虑：[美团企业版到餐接口](https://h5.dianping.com/app/bep-docs/sky-doc/canyinopenapi/daocan_api.html)文档列出门店营业、平均价格和店铺详情，但要求第三方渠道向平台申请凭证；[艺龙酒店详情接口](https://open.elong.com/doc/info/cn-api-search-hotel_detail)能查动态价格、库存和规则，而其[公共协议](https://open.elong.com/doc/info/cn-main-api_list-common_params?menuName=%E6%8E%A5%E5%8F%A3%E5%85%AC%E5%85%B1%E5%8D%8F%E8%AE%AE)要求合作接入及 IP 白名单。它们不是当前个人预览版的默认依赖。[美团联盟商品接口](https://page.meituan.net/html/1701831807616_1db0df/index.html)另提供到餐、酒店、门票商品售价；该售价对应具体商品或券，不能替代完整餐费、酒店房价或景点所有票种。

## 首版采用顺序

1. **餐饮**：高德找候选和参考人均；查得到门店官方菜单时补具体菜品价。只有参考人均时继续标“估算”，菜单与营业资料缺失时保留“待确认”。
2. **住宿**：试验飞猪带入住/离店日期的搜索，并以选中酒店的官方预订页或带日期的商品详情复核；只有同时具备具体酒店、房型、人数、日期、币种、报价内容和查询时间，才展示为“查询时报价”。缺一项即展示候选或跳转入口，不把高德酒店 POI `cost` 当房价。
3. **门票与营业**：先找具体场馆的当期官方公告，再用票务商品补充购买入口和可售价格。常规开放时间若未覆盖用户的出行日、节假日或特展，保留待核实状态。
4. 所有新增信息记录来源链接、查询时间、适用日期、票种/房型、价格性质和核实结果。报价、库存和开放政策在出发前重新检查；冲突时把两条证据都展示给用户。

下一轮最小验证：用同一组杭州—上海周末日期，分别试验飞猪酒店与景点搜索的真实返回字段；为 1 家餐馆和 2 个场馆核对官方菜单/票价/营业页，再决定是否开发适配器。本记录只确认文档和可访问的官方页面，尚未声称新渠道实测可用。
