# 懒人规划 Skill v0.3.0-preview

本阶段优先 AI 客户端内的 Skill，语言理解和推荐使用客户端已有大模型，不需另配模型 API。真实数据来自同一套 12306/高德适配器。网页仍是手动数据联调工具，不能把 Skill 的行为描述当作网页已拥有的功能。

## 用户体验

用户给一句大致意向，例如：“这周末杭州去上海，两天，喜欢建筑和当地小吃，别太累。”

助手提取信息，只补关键缺口，主动推荐片区、景点、餐饮和住宿参考，挑选车站及有票车次，安排两天时间线与轻松备选。所有默认假设、未知费用、营业、预约与接驳边界明确展示。用户不需要提供技术参数或先写景点清单。

之后直接说“这个不喜欢”“第二天轻松点”“晚一小时”“想多吃一点”。助手利用当前上下文更新偏好并查受影响的路线，保留历史与已完成活动，解释修改理由。行程卡快捷按钮只是复制请求，实际理解、查询与重排发生在 AI 客户端。

## 安装与开始

分发目录 `skills/weekend-rush/` 自包含 Skill、参考文档、校验/查询/渲染脚本、固定依赖及许可。复制到支持 Skill 的客户端目录；本机 Codex 已安装到 `C:/Users/LI/.codex/skills/weekend-rush`，并安装了查询依赖。没有改写客户端的 MCP 配置。

新会话中尝试使用 `$weekend-rush` 并给出意向；客户端若尚未发现新 Skill，可明确让其读取安装目录的 `SKILL.md`。本轮验证的是文件安装与脚本执行，尚未独立验证客户端新会话的自动发现。

其他机器：先安装 Node.js 22+，在 Skill 目录运行 `npm ci --ignore-scripts --no-audit --no-fund`，配置自己的高德 Web 服务 Key 环境变量 `AMAP_MAPS_API_KEY`。宿主已有原生 MCP 时可直接使用，无需查询桥；无原生 MCP 但允许本机脚本执行时，桥会按需启动两个固定版本 MCP。依赖安装和网络仍受客户端权限约束。

## 已验证

- 33 项 Node 回归通过，含查询桥部分失败不造数据、完整性提示、未知费用、恶意地点文本转义和冲突显示，以及之前的站点、日期、预算和已完成项保护。
- Skill 官方 `quick_validate.py` 校验通过。使用隔离 PyYAML 依赖及 Python UTF-8 模式，未改系统 Python。
- 在无原仓库父级依赖的隔离目录，按锁文件安装 235 个 npm 包，独立查询到杭州真实车站列表；随后安装到本机 Skill 目录。
- 独立查询桥真实调用成功：往返车次、上海天气、虹桥站、外滩、具体餐饮分店、酒店参考点、人民广场、武康大楼和武康路详情，以及两种节奏所需的相邻路线。
- [完整样例 v1](examples/intent-trip-v1.html) 含两天、吃住玩、交通、休息和推荐理由；[调整样例 v2](examples/intent-trip-v2.html) 以扩展版为基线，将第二天改轻松，第一天与已完成事项保持不变。两份无硬校验错误，但都有未核实信息，不能称全部可行性已验证。
- [校验记录](examples/intent-trip-checks.json) 保留方案检查和逐项变更；JSON 与 HTML 版本同时留存。
- 实际浏览器打开完整行程卡并点击“少走路”，成功复制调整请求，浏览器无 JavaScript 错误；HTML 命令行渲染入口也已执行成功。

案例兴趣、日期、预算和接驳时间是明确标注的开发测试参数；真实车票、坐标和路线有各自查询时间。餐馆菜单/营业、酒店房价/房态、部分具体餐馆、景区内部步行和预约尚未补齐，案例不是已订行程。它验证工具与产物链路，不代表已验证所有自然语言请求或用户满意度。

## 你这一轮怎么验收

1. 自己给一句意向，不提供景点和车次清单。观察助手是否接过推荐工作，只补必要信息。
2. 检查两天是否有具体目的、餐饮与住宿安排，时间、理由和费用边界是否看得懂。
3. 选一个活动说“不喜欢”，看是否换成相关体验并重算前后交通。
4. 再说“第二天轻松一点”，检查第一天、必去点、预算上限和返程约束是否保留。
5. 设一个明显不可行的条件，助手应指出冲突，不能假装满足。
