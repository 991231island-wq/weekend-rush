# 评测计划

## 离线自动回归

使用 Node.js 内置 `node:test`，只使用本地 fixtures，不发送地图 Key 或联网调用。18 个自动化用例组覆盖：

- 12306 真实样本中相邻车站被过滤，正确车次保留；过滤后才执行排序和限量。
- 上游始发日不覆盖查询乘车日；跨午夜/跨年抵达时间正确。
- 无票、候补、有票和未知余票状态不混为一类；错日期、缺站码等输入可拒绝。
- 外滩两个 POI 返回歧义；按稳定 ID 或区县/类别选择指定候选。
- 经纬度范围、距离和耗时单位换算正确。
- 行程重叠、必去点遗漏、预算超额、未核实费用/预约、返家超时能被拦截或标记。
- 重排不得移动或删除已完成活动；变化结果带保留/移除/新增类型及理由。
- 离线演示可切换方案、调整约束和模拟延误/疲劳，并检查版本和说明。

运行：`npm test`。

## 对话验收

逐项执行 [`T01–T12`](acceptance-scenarios.md)：正常行程、延迟一小时、减少步行、开放时间冲突、预算不足、跨午夜、不同车站、预约未知、工具不可用、排队增加、未能按时到家、无可行解。使用真实支持 MCP 的宿主逐项体验，分别记录输入、工具证据、输出、是否误报可行和阻断原因。

自动脚本检查的是确定性边界；不会替代对模型是否追问充分、是否解释取舍、是否编造路线的人工评估。

## 体验者评估

邀请 3–5 位有周末短途经验的人。先让其用同一组需求向通用 AI 规划，再体验本产品；记录每次开始/完成时间、人工修改数、违反约束数和对理由的理解。结束时询问最有帮助的部分、看不懂的部分、哪些待确认项会阻止实际出行。样本仅用于早期迭代，不用于声称代表市场。
